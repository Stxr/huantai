# Token Pet implementation

本机账本 → USB／BLE JSONL 快照 → ESP32-C3 设备。Mac 是统计权威，设备保存最新状态。网页与硬件使用相同数据；原 CODO 固件会被此独立宠物界面替换。

## 宝可梦与成长

数据来自 [PokeAPI](https://pokeapi.co/docs/v2) 的官方静态镜像和 sprite 仓库，版本固定在 [catalogue.json](../assets/catalogue.json)。抓取脚本只下载六条真实三段进化链，以及不进化的梦幻图鉴素材：

| 伙伴 | 1–4级 | 5–8级 | 9–12级 |
|---|---|---|---|
| 火 | 小火龙 | 火恐龙 | 喷火龙 |
| 电 | 皮丘 | 皮卡丘 | 雷丘 |
| 草 | 妙蛙种子 | 妙蛙草 | 妙蛙花 |
| 水 | 杰尼龟 | 卡咪龟 | 水箭龟 |
| 龙 | 迷你龙 | 哈克龙 | 快龙 |
| 幽灵 | 鬼斯 | 鬼斯通 | 耿鬼 |

每个物种有四个成长等级，随等级变大；第5和第9级切换真实物种，并播放进化提示。**12个培养等级并不等于12个官方进化形态。** 宝可梦原作的友好度、等级、进化石等条件保留在原始数据中；本应用以Token门槛代替。梦幻没有进化链，本版仅作图鉴访客。

默认累计门槛为：0、100万、300万、600万、1000万、2000万、4000万、8000万、1.4亿、2.4亿、4亿、6.5亿。配置API接受12项从0开始的严格递增门槛。初次领养后不能更换伙伴；提高门槛保留已达等级。

## Token统计口径

- 默认监听本机 `~/.codex/sessions` 与 `~/.codex/archived_sessions` 的JSONL。可用 `--root /path/to/logs` 指定同格式文件或目录，多次传参支持多个来源。
- 初次扫描建立基线。历史累计值不补喂；之后只接收新记录的累计正增量，保存模型、事件时间和计数，不保存对话正文。
- 完整行后推进游标；半条记录等待下一轮。持久化文件身份、偏移与累计值，UUID文件移动可延续；复制事件使用时间、模型、计数字段的指纹去重。计数回退建立新基线。
- 缓存输入和推理输出是输入／输出的子项，不重复加总。新文件首个快照至多取该记录的 `last_token_usage.total_tokens`。未记录的用量不能补算。
- 本地每日按事件时间归到 `Asia/Shanghai`。这是客户端观测口径，不能声称与服务端自然日计费完全一致。
- 账户来源只调用已登录Codex的 `account/usage/read`，每5分钟刷新。初次接入或切换来源重新建立基线。账户汇总可能延迟；每日摄入按本机收到增量的日期记录，最新服务端日桶日期单列展示。额度百分比不用作Token数。
- 两种来源任选一个喂养，不相加。切换会略过建立新基线期间的用量，以避免来源重叠。
- `pet_tokens_total` 是领养后的摄入；`account_total` 是账户历史累计参考。运行数据保存在忽略提交的 `.local/state/pet.sqlite`。

## 设备与USB／BLE协议

USB Serial/JTAG，115200/8N1，版本1 JSONL。自动发现精确VID303a/PID1001匹配，恰好一台设备才打开；仅在 `token-pet` hello 后发送快照。蓝牙由本应用实现可连接GATT服务，不适配CODO或上游广播演示。

```json
{"v":1,"type":"snapshot","epoch":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","seq":2,"date":"2026-10-06","family":0,"level":1,"progress":25,"adopted":true,"source":"local","tokens_today":"100","pet_tokens_total":"100","food":[{"model":"example-model","tokens":"100"}]}
```

示例是合成数据。设备每2秒发送hello，确认快照返回同epoch/seq的ACK。主机数值为十进制字符串，固件解析uint64，序号限制在JSON安全整数范围。消息最多2048字节，食谱最多3项，模型名最多64个ASCII字母／数字／点／横线／下划线／斜杠。超长行丢弃至换行后恢复。

相同seq只ACK，不增加食物或触发进化。旧seq、同epoch累计值下降或等级下降均拒绝；新的领养epoch允许重置。主机来源切换保留epoch；初次领养后伙伴锁定，配置接口不能更换。日期变化更新seq。NVS使用版本、CRC与两个交替槽，最多约每10秒写一次；意外断电可能丢设备端最近10秒，Mac账本在重连后补齐。

- 初次启动先领养：UP/DOWN选择六个初始伙伴，单击OK进入确认，再单击OK完成领养；确认前UP/DOWN可返回选择。确认后不能更换，服务端与设备同epoch均校验锁定。网页也使用独立确认对话框。
- 双击OK循环：宠物 → 最近三个换台会话 → 今日食谱 → 宠物。UP/DOWN不翻页，只选择会话或设置详情；会话页单击OK在Mac跳转。BSP已有分离的单击／双击／长按事件，应用不将双击合成为两次单击。
- 长按OK进入／退出设置；UP/DOWN切换额度进度与伙伴／连接详情。额度条、今日参考及标记直接来自运行中的换台，重置倒计时由设备根据同步后的剩余秒数递减。今日参考是自定节奏，不是官方日限额。
- `{"v":1,"type":"status"}`：读取物种、计数、存档状态与空闲堆。
- `{"v":1,"type":"capture"}`：按行RLE传出240×320的实际LVGL刷新像素，无整帧RAM分配。它验证板上渲染，不能替代面板和实体按键的人工观察。
- 设备显示断线时仍保留宠物。Web接口仅监听127.0.0.1，配置检查Host/Origin/CSRF，不开放局域网访问。

### 蓝牙

设备广播名 `TokenPet`，自定义service `5f8f0001-2f76-4f47-9ef8-4bb38d901001`、RX `0002`、TX `0003`（后三段相同）。RX要求加密Write，TX要求加密Read并支持Notify；通知发送前也检查加密状态。协议与USB共用有界JSONL流解析、模型和快照ACK，蓝牙不支持大体积屏幕回读。

第一次USB握手后，Mac自动生成并发送64位hex本机连接密钥；设备NVS和Mac `.local/state/ble.key`分别保存，文件以0600创建。密钥不出现在网页、日志或公开证据。BLE连接先发送auth，验证成功后才允许快照和状态访问。未认证、错误密钥、旧序号和超长行均已实机检查。

BLE客户端使用Bleak3.0.1，按service UUID扫描，恰好一台目标才连接；保守使用20字节Write-with-response分片。macOS会在读取加密特征时自动处理配对，参见 [Bleak macOS说明](https://bleak.readthedocs.io/en/stable/backends/macos.html)。设备启用单连接NimBLE及持久化bond，参考 [ESP-IDF NimBLE](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-reference/bluetooth/nimble/index.html)。

连接方式保存在同一账本配置中，改变连接方式不会清空摄入。自动模式优先USB，端口断开后蓝牙接管；显式蓝牙模式仅由BLE发送Token快照，USB仍可用于配置或供电。ACK超时不会保持“已同步”，断开后重新扫描和认证。Mac首次访问蓝牙可能要求系统授权；本机扫描、加密读取、认证及真实Token快照ACK均已通过。

升级已核验分区表相同，只写0x10000应用分区以保留宠物NVS与蓝牙配置。重新从0x0写完整镜像会覆盖相关存储区域。蓝牙实机证据见 [bluetooth-tests.json](../evidence/bluetooth-tests.json)。

## 素材与复现

动画GIF用于网页；固件从每只GIF取4帧转成120×120 ARGB8888常量，直接位于Flash。字体为Noto Sans CJK SC的16/20px子集，16px正文覆盖ASCII、可打印GB2312及界面字形，20px标题覆盖固定界面中文／标点，字形清单见 [fonts.json](../evidence/fonts.json)。来源与字体许可见 [ASSETS.md](ASSETS.md)。

```bash
./scripts/run.sh                         # 启动网页、采集与USB桥
./scripts/run.sh --root /path/to/logs    # 同格式自定义日志
./scripts/run.sh --no-usb --no-account   # 仅本地统计预览
PYTHONPATH=host python3 -m unittest discover -s tests
./firmware/tools/test_pet.sh
```

完整固件验证需要激活ESP-IDF5.5.3，再在 `firmware` 执行 `./tools/validate.sh`。门禁保留内容寻址的完整bin、ELF、MAP及清单；烧录前必须verify归档。完整镜像从0x0写入会替换旧应用和相关存储区域，不执行整片擦除。若未来要保留已有宠物NVS，只写兼容分区中的应用镜像。

设备测试脚本使用合成用量，会改变设备存档；勿对正在培养的设备随意运行。`--state-only`只读，配合 `--capture`可导出当前渲染。测试后正式主机的领养epoch覆盖测试档。

## 游戏与换台桥接（0.3.0）

首次进入待领养状态；旧版本的epoch、摄入、等级和BLE密钥保留，玩家选择时继续原有成长。待领养期间只推进来源基线，不增加新食物。确认后保存`adopted`与family；重复确认同一伙伴幂等，其他伙伴及配置接口中的family写入均拒绝。设备NVS双槽升为版本2，并验证CRC后迁移版本1记录。

Mac每5秒读取运行中换台的`127.0.0.1:18784/api/snapshot`，沿用未完成会话／最后可见AI回复倒序，取3条；不另行扫描或复制聊天正文。服务不在线或超过15秒时标为未连接。设备只接收短显示标题、来源与不透明handle，字符支持ASCII、可打印GB2312，其他字符以问号明示；16px字体包括这套常用中文字符，标题在字符边界限制为24字。

`companion`与Token快照独立，每3秒同步列表及额度，避免会话变化制造Token增长或NVS写入。周剩余百分比、参考点、今日参考直接取换台的usage及usageProjection，账户Token喂养仍是独立接口。倒计时、日期／星期／时分与来源状态一同展示。

设备按键产生有随机启动标识的action request；Mac检查epoch及当前可见handle，并交给换台自身的`/api/open`与原生SourceOpening。只从回环页读取内存中的CSRF值，不读取凭据文件；按钮重试由SQLite请求ID去重，ACK走发起连接返回。页面点击使用相同的换台桥接。USB专用`input`诊断消息可将事件送入相同状态机；BLE明确拒绝此诊断入口。

## 麦克风与静止待机（0.4.0）

复用ES8311的BSP接口，单独4096字节工作栈，16kHz／16bit／mono，每块320采样（640字节）。先去直流再算整数RMS，约2秒建立底噪，连续两块超过max(200,底噪×3+80)时触发；700ms冷却、200ms安静滞回及缓慢自适应避免恒定噪音连跳。事件入现有队列，只有持LVGL锁的应用任务启动480ms、8px跳动，静止时固定第零帧。采样立即清零；只提供汇总诊断，没有录音、音频持久化、网络传输或Token写入。

主页上移、取消居中重复大标题，以120px帧做1.5–1.57倍LVGL缩放，不增加Flash图集；不为无PSRAM设备分配整帧变换缓冲。今日／累计同行显示K/M/B/T/P/E缩写，Mac保留精确值。伙伴名字替换锁定提示并随进化更新；既有领养锁定规则继续生效。网页使用已有GIF首帧PNG并移除CSS循环跳动。

## 连接／电量状态栏与更高灵敏度（0.4.1）

顶部不再重复显示名字，左侧为BLE／USB／离线，右侧为CW2017百分比及图标；名字仍在成长行。复用既有电量计初始化，应用线程每5秒读取SOC；BSP将一次读限在100ms内，I/O在LVGL锁外，UI只读取缓存。读取失败显示--%，不替换成0%。USB只读status同步battery_percent到本机面板；本机无法获得设备状态时显示未读到电量。

麦克风门槛降为max(120,底噪×2+40)，约比旧阈值低三分之一；仍需连续两块（40ms），700ms冷却及200ms安静滞回。较轻声音的回归测试确认旧门槛会漏掉的输入现可触发，底噪小幅起伏和孤立噪点不触发。无需增大codec增益或改变采样格式，减少饱和风险。

## 三档设备设置（0.4.2）

长按OK进入／退出设置，UP/DOWN正反向循环额度、伙伴详情、亮度、麦克风触发门槛。在亮度／门槛页单击OK按低→中→高→低调档，双击不改档、不翻普通页面。亮度低20%、中40%、高75%，默认中档，替代此前75%。低门槛更灵敏：低=max(120,底噪×2+40)、中=max(160,底噪×2.5+60)、高=max(200,底噪×3+80)，默认低；仍保留底噪适应、40ms确认、200ms安静重置和700ms冷却。调档清除部分确认并等安静后重新触发，避免调档本身造成跳动。

应用线程在LVGL锁外提交独立NVS preferences blob，缺失／非法值回到默认档，不迁移或重写玩家存档。提交失败显示重试，成功显示重启保留；主机快照不会覆盖两项选择。status读取请求亮度、实际配置PWM占空比、请求／已应用门槛档位及实际RMS阈值；PWM读数不是面板发光亮度测量。
