# DSH 精确跳转验证

验证日期：2026-11-07（Asia/Shanghai）。独立插件 `@stxr/dsh-session-bridge` 0.1.0；官方 DeepSeek Harness 0.2.2-rc.1，macOS ARM64。

## 交付与使用

插件代码及协议在独立的 [Stxr/dsh-session-bridge](https://github.com/Stxr/dsh-session-bridge) 仓库，换台仓库只维护 Core、App、CLI 和 Web 调用方。插件通过 DSH 插件管理器安装到 **desktop profile**，支持固定 Git 版本或本地目录；如选择目录安装，须保留对应源码目录。开发阶段的换台内嵌包已迁移到独立包，v1 协议保持兼容。

从本仓库构建的换台打开普通 DSH 会话时，会先唤起官方应用，再发现当前实例的动态端口及独立令牌，发送会话 ID 和来源数据目录。只有桌面客户端确认历史已加载、`mainView` 选中了目标会话后，操作才成功。无需手动拼接链接。安装方法、协议及失败状态详见[插件说明](https://github.com/Stxr/dsh-session-bridge#readme)。

## 实装适配

桌面启动器通过 `profileContext` 提供 profile 名和数据根，插件据此决定是否发布桌面发现记录。`connection.rpc.call` 的通道名必须是单路径段。0.2.2-rc.1 的 Host `connection.rpc.handle` 在内部读取 `webServer` 时触发注入错误，因此 Host 使用自己拥有的 HTTP 路由适配公开 JSON 信封，并通过 `connection.admit` 认证 DSH 页面；独立外部入口仍使用插件专有令牌。所有路由由 Cordis effect 管理，在卸载时释放。最终插件不依赖 WebServer 内部路由表，也不修改 DSH 应用包。

## 验证边界

初版支持普通会话，明确拒绝子会话；归档会话需由用户先恢复。数据根目录必须与目标 DSH 桌面实例一致。裸 `dsh://open` 仍然只唤起应用，精确参数由换台内部解释。

真实运行验证使用已运行的桌面应用；冷启动、最小化和隐藏窗口恢复尚未逐项人工验收。普通浏览器验证页需要独立登录，因此未做桌面界面截图和插件管理器图标的可视验收；已核对安装资源中的中英文标题、说明和原创 SVG，真实导航通过桌面 Client 回执验证。
